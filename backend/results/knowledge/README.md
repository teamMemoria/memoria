# Generated evaluation results

These files are generated by `uv run python -m backend.services.knowledge evaluate --split <dev|heldout>`.
Don't edit them by hand. Regenerate them, and commit the result together with the change that caused it.

| File | What it is |
|---|---|
| `eval-dev.{json,md}` | Scores on the dev label sets (`tests/knowledge/labels/*.json`). Rules and thresholds may be tuned against these |
| `eval-heldout-run1.{json,md}` | **The first and only blind held-out run**, kept as it was produced |
| `eval-heldout.{json,md}` | The current held-out scores. These have been re-run after fixing two bugs that run 1 found, so they are no longer blind (see the notes in the file) |

Each report has, per stage, the counts and rates next to the human judgements they were compared with, plus the release
checks over a full pipeline run, technical failures (kept separate from drafts that are only unverifiable), timing and
model usage. Timings change from machine to machine; everything else is reproducible from the same commit.

Verification scores assume a reviewed reference snapshot. The evaluation approves an in-memory copy only. The committed
snapshot stays `unreviewed`.
